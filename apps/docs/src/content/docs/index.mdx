<div class="section-rule">
  <span class="label">What it is</span>
</div>

<p>BulletinMail is an open-source, multi-tenant mailing list service. Every tenant gets a subdomain like <code>firstpresby.bulletinmail.org</code>, with list addresses like <code>announcements@firstpresby.bulletinmail.org</code>. The reference deployment runs at [bulletinmail.org](https://bulletinmail.org); anyone can fork the repo and self-host.</p>

<p>The architectural bet is that <strong>owning the parent domain</strong> — and serving every customer from a subdomain of it — eliminates the two hardest parts of running a listserv: DMARC alignment and IP reputation. Cloudflare's Email Routing + Email Sending stack handles the rest.</p>

<blockquote class="pull-quote">
  <p>Owning the parent domain is the whole architectural bet.</p>
  <cite>— PRD.md, §3</cite>
</blockquote>

<div class="section-rule">
  <span class="label">The notices</span>
</div>

<div class="broadsheet broadsheet--triple">
  <div>
    <p class="smallcaps">No DNS to configure</p>
    <p>The default tier runs under the shared apex. Tenants point nothing. Bring-your-own-domain is a paid-tier feature.</p>
  </div>
  <div class="rule"></div>
  <div>
    <p class="smallcaps">Correct by default</p>
    <p>DMARC alignment via From-rewrite, RFC&nbsp;5322 threading, RFC&nbsp;8058 one-click unsubscribe, RFC&nbsp;2369 List-* headers. mail-tester score: 10/10.</p>
  </div>
  <div class="rule"></div>
  <div>
    <p class="smallcaps">Privacy first</p>
    <p>Archives default to members-only. Public archives require explicit opt-in. Email addresses obfuscated in HTML views.</p>
  </div>
</div>
